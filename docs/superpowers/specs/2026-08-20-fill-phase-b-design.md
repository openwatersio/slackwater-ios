## 1. Region, corpus, and stations

- **Region:** the render clip −125.5..−122.0 × 47.0..50.6 (the seamap bbox, #30).
- **Corpus:** 190 days of hourly surface u/v ending at build date (spec §2: separates
  K1/P1, S2/K2 directly; averages the weather residual), same NODD ranged-read path,
  all region elements. ~4,560 files, ~64 GB transferred once, ~13 GB stored.
- **Mesh:** region element subset now also carries **triangle vertices** (node lon/lat
  via `nv` connectivity) — the fill renders cells, not points.
- **Truth:** all scoreable stations in the region (bundled NOAA + CHS gates via the
  spike's discovery path). The station matrix (FitValidation file mode) runs
  region-wide; §4a grading is **imported from `spikes/sscofs-field/certify.py`** —
  one implementation of the rule, never a fork.

## 2. Shipping fits

- **The shipping fitter is the committed JS artifacts** (`chs-bundle.js` +
  `chs-glue.js`) run in **node** (precedent: `spikes/chs-currents-fit/node-control.mjs`
  — node-control parity is an existing discipline). Per surviving element: fit u and v
  independently (the fitter is a generic harmonic fit; projection linearity already
  conceded in `ChsFitService`).
- **Survivors:** certified (§4a, D = 3 km) ∧ shipping-fit R² ≥ 0.8 on both axes
  (numpy prefilter may cheaply shortlist; the **final** floor is judged on
  shipping-fit residuals).
- **Parity gate before any batch runs:** the node fitter must reproduce a
  FitValidation fit byte-identically on the same samples file (the Task-5 discipline).

## 3. Bundle

- **One committed resource** (`Slackwater/Resources/fill-<region>.bin` + sidecar
  JSON header), generated by `tools/fill-pipeline/`, size-asserted **≤ 40 MB** at
  generation time (expected ~15-20 MB with vertices).
- Header: format version, corpus window, mesh source + hash, D, floors, station-set
  hash, generation date. Constants stable between refits; refit is a release decision
  (fitted-model-does-not-expire semantics).
- Per element: 3 vertices (f32 lon/lat ×3), kept-constituent count, then per kept
  constituent: id (u8), amp f16, phase f16 — ×2 axes. Only survivors ship; masked and
  no-data ship nothing (absence stays absence — the mask IS the missing element).
- Constituent id table lives in the header (names → u8), pinned to the shipping basis.

## 4. Swift provider (the seam's channel-2 sibling)

- `FillField`: loads the bundle lazily, evaluates per-element u/v at time t via
  TideEngine's constituent machinery, and vends the agreed payload: cell polygon +
  speed (kn) + bearing (deg true, free from u/v — the streak channel may want it).
  Same evaluate-at-t contract as the particle seam; absence stays absence (an element
  not in the bundle is simply never vended).
- No timing semantics, no green: the provider vends magnitude + geometry; ramp and
  drawing are the render layer's (#57 session), bound by the no-green rule.
- Tests: bundle round-trip (pack → load → constants match), evaluation against a
  known-constituent synthetic element, and a golden test pinning one real element's
  speed at a fixed instant.

## 5. Out of scope

Render layer & edge treatment (#57 seam consumer); grown patches; timeline scrubber;
any CHS-derived data in the bundle (SSCOFS-only — the licence story stays trivial);
non-Salish regions (the format carries a region tag; more regions are more files).

## 6. Success criteria

1. Region bundle committed, ≤ 40 MB asserted, loadable offline.
2. Every shipped element traces to: certified station (§4a) + shipping-fit R² ≥ 0.8.
3. Node-fitter parity with FitValidation proven before batch fits.
4. Provider golden test green; no app-target regression (existing suite green).
5. Pipeline reproducible end-to-end from `tools/fill-pipeline/README.md`.
